# API-13 선수 상세 조회

2026 LCK 한 시즌의 선수 기본정보와 요약 카드를 반환하는 기능입니다.

- 기준: [노션 API 명세서](https://app.notion.com/p/API-40f07de9b4c280b483fffec0b3642df0)
- 공통 응답 표현: [경기 API 변경 안내](https://app.notion.com/p/API-41b07de9b4c281749954ce872aac9ca2)
- CS 평균과 등급 산식: 확정 화면설계서의 요약 카드 및 ‘등급·세트 평점 기준’을 따릅니다.

## 호출 방법

`GET /api/v1/players/{playerId}`

| 선택 항목 | 의미 |
| --- | --- |
| `patch` | DB에 저장된 패치 버전입니다. 예: `26.8`. 앞뒤 공백을 제거하며 빈 값은 필터 없음입니다. |
| `championId` | 특정 챔피언으로 출전한 기록만 조회하는 양수 ID입니다. |

두 필터를 함께 보내면 두 조건을 모두 만족하는 기록을 조회합니다.
선수 ID와 챔피언 ID는 실제 DB의 값을 사용해야 합니다.

```text
/api/v1/players/13
/api/v1/players/13?patch=26.8
/api/v1/players/13?patch=26.8&championId=136
```

위 번호는 호출 형식의 예시입니다.

## 코드가 처리하는 순서

1. `PlayerController`가 프론트의 요청을 받습니다.
2. `PlayerService`가 입력값과 선수 존재 여부를 확인합니다.
3. `PlayerStatisticsRepository`가 필터에 맞는 세트 기록, 당시 팀의 전체 킬, 같은 포지션의 비교 자료를 읽습니다.
4. `PlayerService`가 요약 통계와 날짜 범위를 계산하고, 필요한 경우 저장된 시즌 점수에서 등급을 구합니다.
5. `PlayerDetailResponse`가 결과를 JSON으로 전달합니다.

`PlayerProfile`은 기본정보를 담는 내부 자료형입니다. 이것만으로 전체 응답을 구성하지 않습니다.

## 반환 내용과 계산 기준

| 항목 | 계산 및 의미 |
| --- | --- |
| `playerId, name, position, team` | 선수 ID, 게임 닉네임, 주포지션, 현재 소속 팀입니다. |
| `filter.fromDate, toDate` | 필터에 맞는 출전 기록의 최초·최종 경기 날짜입니다. 별도 날짜 입력 항목은 없습니다. |
| `sets, wins` | 출전 세트 수와 승리 세트 수입니다. 경기(시리즈) 수와 다릅니다. |
| `winRate` | 승리 세트 수 / 출전 세트 수입니다. 65%는 `0.65`입니다. |
| `kills, deaths, assists` | 선택된 기록의 누적 합계입니다. |
| `kda` | (누적 킬 + 어시스트) / max(누적 데스, 1)입니다. |
| `teamKills` | 선수가 출전한 당시 팀세트에 속한 전체 선수의 킬 합계입니다. 이적 후 현재 팀과 구분합니다. |
| `killParticipation` | (누적 킬 + 어시스트) / 팀 킬입니다. 0~1 비율입니다. |
| `csPerMin` | 세트마다 (미니언 + 몬스터 처치 수) / 경기시간(분)을 구한 뒤 산술평균합니다. |
| `positionAvgCsPerMin` | 선수 주포지션과 같은 실제 출전 포지션의 세트 기록에 동일 시즌·패치·챔피언 조건을 적용한 CSM 평균입니다. 본인 기록도 포함됩니다. |
| `avgRating, bestRating` | 공통 `Rating.fromPoints`로 세트 점수를 평점으로 변환한 뒤 평균·최댓값을 구합니다. |
| `pogCount` | 선택된 세트 중 POG로 저장된 횟수입니다. |
| `grade, gradeAvailable` | 저장된 시즌 점수의 등급과 표시 가능 여부입니다. |

승률·킬 관여율은 소수 4자리, KDA·CSM은 2자리, 평균 평점은 1자리에서 반올림합니다.
경기시간이 0초인 기록은 분당 지표의 평균에서 제외합니다.
팀 킬을 구할 때 팀원에게 대상 선수의 챔피언 필터를 적용하지 않습니다.

2026-01-01 이상, 2027-01-01 미만의 경기 기록을 사용하며, 플레이오프도 포함합니다.
DB 자체에는 이번 프로젝트의 2026 LCK 시즌 자료를 적재해야 합니다.

## 등급과 데이터가 없는 경우

등급을 제공하려면 활성 필터가 없고, 대상 선수의 2026 출전 기록이 10세트 이상이며,
`player_season`에도 10세트 이상의 계산된 종합 점수가 있어야 합니다.

화면설계서의 `상위 % = 100 - 종합 점수`를 적용합니다.
상위 5/15/25/40/55/70/85% 이하가 각각 A+/A/A-/B+/B/B-/C+이며, 나머지는 C입니다.
같은 점수는 같은 등급입니다. 종합 점수를 다시 선수 순위로 변환하지 않습니다.

- 필터가 있거나 표본·시즌 점수가 부족하면 `grade=null`, `gradeAvailable=false`입니다.
- 선수는 존재하지만 선택된 기록이 없으면 HTTP 200과 기본정보를 반환합니다.
- 횟수·합계는 0, 계산할 수 없는 비율·평점·개인 CSM·날짜는 null입니다.
- 개인 기록이 없어도 리그의 비교 자료가 있으면 `positionAvgCsPerMin`은 반환할 수 있습니다.
- 세트 점수가 null인 기록은 평균·최고 평점 계산에서 제외합니다.

## 기존 명세 예시와 맞춘 공통 규칙

- 포지션은 최근 경기 API와 같이 `TOP, JUNGLE, MID, ADC, SUPPORT`를 사용합니다.
- 팀 테이블에 전체 이름이 없어 `team`에는 `teamId, code`만 반환합니다.
- 오류는 기존 공통 형식 `status, code, message`를 사용합니다.
- 잘못된 ID·자료형·허용 길이를 넘는 패치는 HTTP 400 / `COMMON_001`입니다.
- 없는 선수는 HTTP 404 / `PLAYER_001`입니다.
- 존재하지 않는 패치·챔피언 필터는 일치하는 기록이 없는 조회로 처리합니다.

## 다른 도메인과의 관계

API-13은 팀과 경기 관련 데이터가 필요합니다.
이미 공유된 엔티티의 관계를 통해 선수세트의 경기 날짜·시간·패치·승패와 팀 정보를 읽습니다.
팀 순위 조회나 홈 API를 호출하지 않으므로 해당 PR의 병합을 기다리지 않고 동작합니다.

반면 실제 통계를 표시하려면 원천 CSV 기록이 DB에 있어야 합니다.
평점·POG·시즌 점수는 기존 적재·재계산 작업의 결과를 읽습니다.
이번 조회 구현에서 B3/B4 점수 계산이나 CSV 적재를 추가하지 않았습니다.

API-12 목록, API-14 종합, API-15 경기 기록과 홈용 `PlayerSeasonReader` 구현은 별도 작업입니다.

## 검증

`PlayerControllerTests`는 실제 MySQL과 요청 처리 경로를 사용하며, 테스트 데이터는 각 검사 후 롤백합니다.
리그 전체 비교 평균을 검증하므로 기존 실데이터가 없는 별도의 검사용 DB에
`src/main/resources/db/schema.sql`을 적용하고 DB 연결 환경변수를 지정한 뒤 실행합니다.

```powershell
.\gradlew.bat build --console=plain
```

주요 검사는 통계 합계, 필터 AND 조건, 이적 전 팀 킬, 평균의 분모, 0·null 처리,
2026년 경계, 등급 조건, 공통 오류 응답입니다.

2026-11-19 검증에서는 별도의 빈 MySQL 8.0.46에 기존 스키마를 적용하여
전체 빌드와 테스트 132개를 통과했습니다(실패·오류·건너뜀 0개).
선수 관련 검사는 HTTP·DB 통합 38개, 등급 경계 19개, 기본 조회 10개입니다.
OneDrive의 기존 검사 결과 폴더 잠금으로 결과 출력 폴더만 외부 임시 위치로 지정했습니다.
테스트 데이터는 롤백됐으며 임시 MySQL 서버는 검사 후 종료했습니다.
